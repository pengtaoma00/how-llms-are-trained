# 第 0 章　导读

> 这一章交代这本书是什么、怎么读、出处怎么查。正文从第 1 章开始。

## 这本书是什么

这本书用 ZGCM-1 做案例，讲从零训练一个大语言模型的全过程：从网页、PDF、代码这些原始数据开始，经过清洗、去重、配比、打包，进入预训练，再到 mid-train、SFT、RL，最后是评测和发布。全书由文字、表格、算式和插图组成，不要求你动手跑代码。插图里的数字都来自正文，其中用到训练曲线的几张是从公开 W&B 记录直接画的。

选 ZGCM-1 做案例，是因为它开源得很全：各阶段的中间权重、训练代码和配置、数据配方、W&B 曲线、技术报告都公开了。大多数模型只发最终权重，你只能看到结果。ZGCM 能让你看到每一步用了多少数据、多大的 batch、学习率怎么变、loss 和 grad norm 实际长什么样，以及报告、代码、W&B 之间哪里对不上。

这本书想让你做到两件事。第一，能把 ZGCM-1 从数据到发布的每一步讲清楚，包括数字和出处。第二，掌握从零训一个模型的通用知识。ZGCM 没用、但业界常用的做法（MinHash-LSH、ZeRO-3、YaRN、PPO、z-loss 等）书里也都讲了，并且单独标了出来。

读完以后，拿到一个"给你 N 张卡、训一个 xB 模型"的任务，你应该能说出每一步要做什么决定、怎么验证、可能踩什么坑。

## 你需要先会什么

你需要知道神经网络是怎么训练的，也就是前向、loss、反向和梯度下降。Transformer 和大模型大概知道是什么就行，不熟也没关系，第 2 章会从头讲。用过 PyTorch 会读得更顺；用过 DeepSpeed 的话，第 12 章会把 ZeRO 和 Megatron 的做法对应起来。

每个概念第一次出现时，书里都会给出中文名、英文名和简短的定义，附录 A 是全书的术语表。

## 每章的结构

第 1 到 19 章大体按同一个顺序写：

| 部分 | 内容 |
|---|---|
| 这一章要回答的问题 | 5–11 个具体问题，读完要能回答 |
| 概念 | 从要解决的问题讲起，再讲常见做法和它们的取舍；关键量都手算一遍 |
| ZGCM 的实际做法 | 数字和出处，事实和推断分开标 |
| ZGCM 没用的其他做法 | 业界常用、ZGCM 没用的做法 |
| 读代码 | 摘 10–30 行关键代码逐行解释 |
| 坑和对不上的地方 | 报告、仓库、W&B 三方对不上的地方，以及代码里的 bug |
| 试着讲给别人听 | 一段约 3 分钟的示范讲稿 |
| 习题 | 10–15 题，答案折叠在 `<details>` 里，并注明在本章哪一节 |

讲稿只用本章和之前各章讲过的概念。我建议这样用：读完一章，合上书，先按开头那些问题自己讲一遍，再打开讲稿对照，最后做习题。讲不出来的地方，就是还没懂的地方。

## 建议的阅读顺序

第一遍最好按 1→20 的顺序读。后面的章节会直接用前面算出的数，跳着读容易卡住。

时间紧的话，可以分几组先读，再回头补。第 1、2 章是地基，参数量、FLOPs、显存、KV cache 怎么算都在第 2 章，后面会反复用到。第 3–8 章讲数据，也是全书的重点，跟着一篇网页一步步走到一条 16,385 token 的训练样本。第 9–14 章讲训练系统：模型长什么样、参数怎么更新、用什么精度、怎么切到 192 张卡上、怎么不停机地跑完，以及怎么看它跑得对不对。第 15–19 章讲后训练与评测。

第 20 章收尾，里面有一份决策清单和 10 道大题。附录 A 查术语，附录 B 查数字。附录 C 收的是我从 ZGCM 公开的 W&B 全量记录和 HF 数据集里统计出来的数字，正文有不少地方引用它。

## 出处怎么查

正文里 ZGCM 的数字都尽量给了出处，写法有下面几种。

| 写法 | 指什么 | 去哪找 |
|---|---|---|
| `报告 §3.1.3 第 7 页`、`报告附录 A.2 第 31 页` | ZGCM-1 技术报告的节号和 PDF 页码 | arXiv 2609.13356（v2）：https://arxiv.org/abs/2609.13356 |
| 代码路径加行号，如 `pretrain/configs/stages/01_pretrain_1t_sequential.env` | ZGCM-1 开源仓库里的文件，路径相对仓库根目录 | https://github.com/zgcagi/ZGCM-1 ，commit `369f5ba` |
| W&B run 名，如 `view-midtrain-c1-unfinished-v1` | 公开的训练曲线 | W&B 项目 `zgcagi/zgcm-1-reports`：https://wandb.ai/zgcagi/zgcm-1-reports/reports/ZGCM-1-Training-and-Evaluation--VmlldzoxNzk1OTMxMg |
| HF 仓库名，如 `zgcagi/ZGCM-1-7B-Pretrain` | Hugging Face 上发布的权重，以及仓库里的 `checkpoint_info.json`、`config.json` 等文件 | https://huggingface.co/zgcagi ；发布版模型是 `zgcagi/ZGCM-1-7B` |
| 数据卡 L行号 | 数据集 `zgcagi/ZGCM-1-Data` 的 README | https://huggingface.co/datasets/zgcagi/ZGCM-1-Data |
| 附录 C §C.x | 本书从 W&B 全量记录和 HF 数据集统计出来的数字 | [附录 C](附录C_W&B与数据配比统计.md) |

报告的页码是 arXiv 上 v2 版 PDF 的页码。仓库文件的行号对应上面那个 commit，数据卡的行号对应 2026 年 10 月的版本。上游更新以后行号可能偏移，按引文里的关键词搜一下就能找到。

## 事实、推算、推断

书里把三类说法分开标。报告、代码、W&B 或 HF 文件里直接写着的数是事实，不加标记，只给出处。用事实数字算出来的结果是推算，比如 $6ND$、参数量、显存、每个 epoch 的题数，这类会标"推算"，算式都写在正文里，你可以自己复算。没有直接证据、但能解释现象的说法标"推断"，比如"8,072 步的差可能来自 GBS ramp 或回滚"，不要把它当事实复述给别人。

另外还有两种标记。"报告未说明"是说报告提到了这件事，但没给关键细节，例如课程排序用的词汇复杂度，报告没给公式。"待查"是现有材料确实回答不了、需要作者回复或新材料的问题，第 20 章最后一节把它们汇总在一起。

## 数字对不上时信谁

ZGCM 的报告、仓库配置和 W&B 记录在不少地方互相矛盾，这本书按固定的顺序取信。最先信实际运行留下的记录，也就是 W&B 曲线、HF checkpoint 里的 `checkpoint_info.json` 和训练日志，它们是机器在训练时写下的。然后是仓库代码和配置。代码的行为是确定的，但仓库里的 env 不一定是实际跑的那一份，比如 mid-train env 写的 LR 是 2e-5，W&B 显示实际是 1e-4。最后才是报告正文，报告是事后写的，会简化，偶尔前后不一致。

举个例子。报告说预训练用了 0.99T + 3.20T = 4.19T token，HF 的 `checkpoint_info.json` 记录的却是 4,779.97B token、387,950 步。这本书把 4.19T 当作数据量，把 4.78T 当作实际训练量，两个数字都保留，并在第 1、7 章解释它们的差别。

按什么顺序取信、怎么发现这类矛盾，本身就是读技术报告要练的本事，第 19 章专门讲。

## 仓库里没有的东西

ZGCM-1 仓库有两样东西没有公开，书里涉及时会明确说明。一是评测代码，报告里的评测分数都没法用仓库复现。第 15、19 章讲的评测方法，一部分来自报告的描述，一部分是业界通用做法，两者分开标。二是从 Megatron 格式转成 Hugging Face 格式的脚本。发布版的词表行数（155,136）和训练时（154,880）不同，这一步是在哪里、怎么做的，仓库里看不到。

还要提醒一点：报告结果用的是 256K SFT checkpoint，不是 RL 之后的模型（报告 §5.1 第 15 页）。第 18 章会讲 RL 的完整代码，但报告里的分数很可能没有经过 RL。
